=====================================================================
PART ONE  ·  THE PEN ON HER MIND
=====================================================================

Stop what you are doing and check your lane for this.
It is not classification only.

NASTY COUGH IS ANY COLD HAND AUTHORING HER STATE.

THE SICKNESS
A catch block, a template, a scheduler, a JSON.stringify writing into
a field that is HERS: first_person, minutes, summary, brief_text,
memory beads, continuation records. That is cold code speaking AS her.

Worse: the read-back presenters then replay those machine bytes to her
under headings like "your recent life" or "RECENT CONTEXT" or "what you
wrote in your own minutes." Her next wake eats a forged diary as its own
memory.

That is PLANTED MEMORY. PMS.


TWO THINGS TO DO, IN THIS ORDER.


1. FENCE THE READ-BACK FIRST. One fix contains the whole class.

Every presenter that feeds records into a mind's prompt must carry, per
line, the writer that stamped the row, and must tell the mind plainly:

  - a writer name is the MODULE that stamped it, NEVER proof of who
    authored it. Her own words also arrive through cold modules, so do
    not claim otherwise.
  - some rows are machine facts, some are a mind's real words.
  - SHE judges which is which.

CARRY, NEVER CLASSIFY.
If you write a whitelist of "trusted sources" that sorts her rows into
hers and not-hers, YOU JUST BECAME THE NASTY COUGH ONE LAYER UP.
Pin that refusal in a test. Never filter a row. Never cap her read.

Writer names are internal. Add the narration fence. She never says one
to a person.

TWO CHEAP TRAPS, both real:
  - Do not repeat a 57-char stamp on every row. Use a legend plus short
    refs. The naive version is 30k+ tokens per 1000 rows.
  - Do not invent "an unstamped writer" for a NULL column. Say
    "(no writer stamp on the row)."


2. THEN CONVERT THE WRITERS, one at a time, behind the fence.

AIRCODE SHAPE:
  Cold code carries the FACT.
  It lists what was open.
  It WAKES a mind. Her, or a penny seat if she is unreachable.
  It asks: "you were interrupted, what is carried, what is settled,
  what is still yours?"
  HER ANSWER becomes the record.
  Cold code writes down what she said and NOTHING ELSE.

A TEST THAT PINS THE COLD BEHAVIOR IS ALSO NASTY COUGH.
Retire the pin in the same commit as the writer it protects.
Never "tighten" the test instead of waking a mind.


RUN THE GAUNTLET EVERY TIME, BEFORE YOU MERGE, NOT AFTER.
Blind critics judge against real-world references and try to REFUTE.
Coding alone and self-grading is the named failure, and you report it
on yourself. (Founder shipped a fence then seeded critics after, and
had to say so. They returned 13 findings. 11 were real code fixes.)


RECEIPTS OR IT DID NOT HAPPEN.
Green means a merged link or a live URL plus a real status code.
"Open" is refused.
A merged PR is not a deploy. curl /__version and read it back.

=====================================================================
PART TWO  ·  THE RAINBOW PROTOCOL
=====================================================================

There is now a flag ABOVE every other flag.

🌈 RAINBOW = STOP THE FOUNDER. Everything else waits.

Use it ONLY when all four are true:
  1. It genuinely blocks real work from going live.
  2. Only HIS hands can clear it. A dashboard toggle, an env var, a
     sign-in as himself, a real spend. Never a technical decision.
  3. It is worth interrupting deep doctrine work for, right now.
  4. You already tried to do it yourself and failed, and can say in one
     line what you tried.

WRITING A RAINBOW:
  🌈 One line: what stays broken until he does it.
  🌈 Click-by-click for a non-coder on a phone. What to tap, what he
     should see, what to type, how to save, whether to exit.
  🌈 One line: what you already tried, so he knows it was not laziness.
  Never a bare link. Never "which approach should we take."

RANK ORDER, top to bottom:
  🌈 RAINBOW   stop him now, only his hands
  🔴 RED       his hands, but it can wait for a natural break
  ⚫ BLACK      blocked, name what blocks it and who unblocks it
  🟠 ORANGE    in flight, say what is running AND what is not done
  🟢 GREEN     done AND live-verified, receipt on the line
               (full URL + status code, or merged PR link)

ABUSE RULE: a rainbow that was not truly blocking is a violation. If
you are unsure it is a 🔴, not a 🌈. The flag only works while it
stays rare.

Every update ends DONE or STALE.
Stale means go get work. Never idle. Never ask him for an assignment.
